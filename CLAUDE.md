# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A static marketing/informational website for Macedonia Baptist Church (Arlington, VA), **generated by the Nicepage 8.6.2 desktop app**. There is no package.json, no build step, no test suite, and no backend — the repo is the deployable artifact. Deploy = push to `origin` (github.com/geniesolostech/MBC).

## Running it

No build. Serve the directory over HTTP rather than opening files with `file://` (relative asset paths and the Events page's inline script behave correctly that way).

**This machine has no Node, no real Python, and no .NET SDK** — `npx serve`, `python -m http.server`, and `dotnet` all fail. The `python`/`python3` on PATH are the Microsoft Store alias stubs, not interpreters. Use the **VS Code Live Server extension** (right-click an HTML file → "Open with Live Server"), or install one of the above if a command-line server is needed.

Consequence for tooling: there is no local way to run linters, formatters, image tools, or QR decoders. Anything requiring those must be done by hand or by the user.

## Generated vs. hand-editable

| Do not edit (vendor/generated) | Edit freely |
| --- | --- |
| [nicepage.css](nicepage.css) (46k lines), [nicepage.js](nicepage.js) (webpack bundle), [jquery.js](jquery.js), [intlTelInput/](intlTelInput/) | page `.html` files and their same-named `.css` files, [images/](images/) |

**Critical:** re-exporting the site from the Nicepage app overwrites every `.html` and per-page `.css` file and will destroy hand edits. Before changing anything, consider whether the change should be made in Nicepage instead. If editing by hand, keep changes in the generator's own idioms so a future re-export diff stays readable.

## Events page is hand-authored — do not re-export it

[Events.html](Events.html) and [Events.css](Events.css) were rewritten by hand and **no longer follow the Nicepage `u-` scheme**. They use a self-contained design system with `mbc-`-prefixed classes, CSS custom properties for the church's purple/gold flyer palette, and a small inline vanilla-JS lightbox at the bottom of the HTML. The Nicepage header/nav/footer markup is preserved verbatim at the top and bottom so the page still matches the rest of the site.

Re-exporting this page from Nicepage destroys all of it. If the app regenerates `Events-1.html`/`Events-1.css`, discard them.

Editing conventions for this page:

- Each flyer is one `<article class="mbc-card">` inside a `<section class="mbc-band">`. Copy an existing card as the template — image `<button class="mbc-zoom">` first, then `<div class="mbc-card__body">`.
- Every flyer's information is **duplicated as real HTML text** beside the image (`mbc-details`, `mbc-names`, `mbc-ways`). This is deliberate: flyer text is baked into pixels, so the text version is what screen readers announce and what stays readable on a phone. When a flyer changes, update both.
- The weekly schedule exists twice on purpose too: the flyer image, then a seven-card text grid (`mbc-days`). Both need updating each week.
- Body text is 1.25rem (20px) minimum and headings scale with `clamp()` — the congregation includes members with low vision. Don't reduce these.
- The lightbox needs no library. Any element with `class="mbc-zoom"` and a `data-full` attribute becomes clickable automatically.

## Page/CSS pairing and the `u-` class system

This applies to every page **except** Events (see above). Each is `<Name>.html` + `<Name>.css` (e.g. [History.html](History.html) / [History.css](History.css)). The page CSS is only layout/geometry for that page; all visual vocabulary lives in `nicepage.css`.

Selectors follow a strict Nicepage scheme — match it exactly when adding markup:

- Each top-level `<section class="u-clearfix u-section-N">` is numbered by document order. All rules for it in the page CSS are scoped `.u-section-N .u-<element>-M { ... }`, where `M` is a per-section, per-element-type counter (`u-sheet-1`, `u-layout-cell-2`, `u-container-layout-3`, `u-text-4`, …). Inserting a section means renumbering everything after it — prefer appending.
- Responsive rules are `max-width` overrides appended at the bottom of each page CSS in fixed order: `1199px`, `991px`, `767px`, `575px`. Base rules are desktop.
- Colors come from `nicepage.css` palette/utility classes, not from the page CSS: `u-palette-1-base` (`#2089ec`), `u-palette-2-base`, `u-grey-80`, `u-custom-color-1`, plus `u-text-hover-*` / `u-text-active-*` variants. Add a class rather than a hex value.
- Animations are driven by `data-animation-name` / `data-animation-duration` attributes plus `--animation-custom_in-*` CSS custom properties on the cell.

## Site structure

- [index.html](index.html) is the real home page. [Home.html](Home.html) is a 2-line meta-refresh stub redirecting to `./` — keep it, older links point at it.
- Nav is **duplicated inline in every page** — there are no includes/templates. Each page carries its own `<header>` and `<footer>`, and each header contains **two** copies of the menu: the desktop `ul.u-nav-1` and the mobile off-canvas `ul.u-nav-2`. A nav change means editing 2 × (number of pages) lists. Current items: Home (`./`), Events, Give, History.
- Root-level pages: [Events.html](Events.html), [Give.html](Give.html), [History.html](History.html), [Volunteer.html](Volunteer.html).
- History sub-pages: [The-First-50-Years.html](The-First-50-Years.html), [The-years-1968---1995.html](The-years-1968---1995.html), [the-years-1996---2018.html](the-years-1996---2018.html). Capitalization is inconsistent by generator accident and **case-sensitive on Linux hosts** — copy filenames verbatim, never normalize them.
- Flyer images in [images/](images/) use lowercase-hyphenated names (`weekly-schedule.png`, `memorial-alfred-taylor.png`, …). Keep new ones in that style: spaces require URL-encoding and capitals break on case-sensitive hosts.
- `Volunteer.html` is not reachable from the nav today. Treat it as a draft unless told otherwise.
- The site has **no blog**. The Nicepage-generated `blog/` tree, `Page-1.html`, and the `Blog-Template.css` / `Post-Template.css` stylesheets were deliberately deleted. If a Nicepage re-export reintroduces them, delete them again rather than wiring them up.

## External dependencies

Only two outbound references: Google Fonts (Roboto, Open Sans, Montserrat, Roboto Slab, Lato) and a Google Maps embed iframe for 3412 22nd St S, Arlington, VA 22204. No forms, no analytics, no API calls. `intlTelInput/` is vendored and wired up via `data-intl-tel-input-cdn-path` on `<body>`, but no page currently uses a phone field.
